# Native Helper Boundaries

ADR 0001 reserves separate packages for policy (`Z4`), execution (`Z5`), and
audit (`Z6`). A P2.5 grant proof helper in `Z4` binds the pure policy result, exact action plan,
fresh service-local test approval, durable audit acknowledgement, and signed
checkpoint before creating a one-use no-effect grant. It is unreachable from
the application and has neither production grant nor effect authority. The audit root
contains the accepted P2.3 isolated journal plus the accepted P2.4 offline,
software-backed checkpoint and Rekor protocol baseline. An accepted standalone
Swift helper adds only a packaged, owner-gated Secure Enclave lifecycle proof;
Electron has no path to invoke it.

Accepted process ownership v11 permits one application-unreachable, test-only
Swift watchdog control fixture in `Z5`, an anonymous in-process XPC transport,
and an uncomposed typed client over an injected transport. The accepted inert
core mutates only embedded capsule records. The proposed transport
implementation applies exact peer code-signing requirements on both anonymous
endpoint connections, admits only watchdog v1 dictionaries, and fails closed
for an ad-hoc-signed peer. The owner-authorized identity selector
`UMXN25Z493` signs with actual TeamIdentifier `3RD3TADLRY`; their mismatch was
rejected fail-closed. After the owner authorized the actual TeamIdentifier, a
fresh Apple Development-signed anonymous fixture authenticated on both
connections and verified disconnect reduction over terminal inert records.

The fixture exposes no named Mach service, registration, application
composition, PID, VM, process, filesystem, network, reconciliation, journal,
ownership-release, or production authority.

Accepted process ownership v15 authorizes the static-only package gate: place
the accepted anonymous fixture under `Contents/Library/LaunchServices` and
verify nested and outer test signatures. The implementation adds no LaunchAgent
plist, ServiceManagement call, registration, named listener, runtime app path,
or packaged-executable invocation. Accepted process ownership v16 binds the
physical signature, package-layout, no-launch remediation, and final source
postimages.

Accepted process ownership v17 is the current source-only gate. It fixes one
test-only executable identity, Mach service name, expected DOSAI client
identity, and TeamIdentifier for a compile-only inactive-listener candidate.
It permits no executable output, package change, plist, activation,
ServiceManagement operation, registration, launch, application connection, or
effect authority.

That v17 slice is implemented as one compile-only, fixed-name inactive listener
candidate, and accepted process ownership v18 binds its source, test, and
successful arm64 macOS 15 typecheck. Accepted process ownership v19 permits only
a compile-only shared strict service handler and fixed named-listener adapter;
that slice is implemented and proposed process ownership v20 binds its final
bytes. Process ownership v20 is accepted. Accepted v21 permits only one fixed
service entry point and a temporary unsigned link proof with default Apple
Silicon ad-hoc signing explicitly disabled. That proof is implemented, and
accepted v22 binds its final evidence. No executable persists, and signing,
package entry, plist, registration, launch, application connection, or runtime
effect authority remains unavailable.

Accepted process ownership v23 defines the static-only package gate for the
named-service executable. The owner authorized test-only signing of the exact
nested named-service fixture and containing app with selector `UMXN25Z493` and
TeamIdentifier `3RD3TADLRY`. The fixed builder, package mode, and adversarial

evidence and seven successor-aware guard updates. The generated package was not
invoked. Plist, registration, launch, and application connection remain
unavailable.

Accepted process ownership v25 separates declaration review from package and

Accepted process ownership v27 separates static plist-bearing package
composition from registration. It defines one distinct fixed package mode and

registration, loading, launch, application connection, and production use

Accepted process ownership v29 separates observational Service Management
status modeling from lifecycle mutation and authorized only one compile-only
fixed-plist status candidate plus one adversarial source test. Both are now
implemented, and accepted process ownership v30 binds their exact bytes,
arm64 macOS 15 typecheck, denial observations, and twelve successor-aware guard
remediations. The source was never invoked or compiled to an executable.
Registration, unregistration, opening System Settings, executable output,
packaging, invocation, launch, and application connection remain unavailable,
and `ENABLED` would not by itself prove service liveness or authenticated
reachability.

Accepted ADR 0021 selects a future status-only native Node-API bridge loaded by
a dedicated Electron Main adapter. Accepted process ownership v31 reserves one
separate Z3 native-addon root, one Main adapter path, and one adversarial test
path. Those exact paths are now implemented source-only, and accepted process
ownership v32 binds their bytes, fail-closed admission, and two successor-aware
guard updates. Accepted v33 selects only the four hash-locked C Node-API headers
from the canonical accepted Node 24.18.0 archive installation, which exactly
matches Electron 43.2.0's embedded Node, and authorizes explicit Node-API v8 plus
one temporary unsigned compile proof. The proof now compiles, links, inspects,
and deletes an arm64 macOS 15 bundle without loading it; accepted v34 binds the
exact source, adversarial test, canonical-layout rejection, binary observations,
and cleanup evidence. Accepted v35 then reserved a distinct static mode for the
addon plus the accepted plist-bearing named-service app, and the owner separately
authorized exact test-only nested and outer signing. That slice is implemented:
accepted v36 binds the fixed builder, package mode, adversarial retained-artifact
test, exact signed identifiers and layout, arm64 macOS 15 and ServiceManagement
linkage observations, bounded Node-API symbols, 23 successor-aware guards, and
the disclosed discarded matcher attempt. No module, app, service, or helper was
loaded or invoked; no status call, registration, launch, or connection occurred.
Accepted process ownership v37 implements only a dedicated no-window, one-shot
Electron Main test bundle, bounded source selection, a fixed audit runner, and
an adversarial source test for a later signed-app physical status proof. It grants
no package build, signing, app launch, module load, status call, registration,
service launch, or connection authority; a separate exact physical authorization
remains required.

No implemented helper has application process-execution, network, production
credential, production signing, or external-anchor write authority. Each new authority still
requires its owner-phase contract, build, signing, entitlement, transport, and
adversarial proof before activation. Current accepted boundaries are machine-
enforced by accepted `docs/architecture/process-ownership-v36.json`; later
generations must remain hash-bound to immutable accepted predecessors.
